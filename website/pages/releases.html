Four assets per release.

mantle-VERSION-x86_64-unknown-linux-musl.tarStatic bin/mantle-egress, bin/mantle-launch, bin/mantle-worker; the same notices plus MUSL_COPYRIGHT for musl 1.2.5.
SHA256SUMSChecksums of the three files above.

For 0.2.0 the manifest records glibc 2.39 and rustc 1.97.1. GNU compatibility is limited to that recorded runtime; older glibc, macOS and ARM are not claimed. Archive metadata is deterministic (zero timestamps and owners); that does not promise bit-identical compilation on other toolchains or hosts. Releases 0.1.0 to 0.1.4 are source archives only.

03 / Verify and install

What each step proves.

The commands are on the start page.

  1. Download from the release page and compare source_commit in manifest.json with the tagged commit. Keep the manifest, both archives and SHA256SUMS in one directory.
  2. Check both archives against the manifest with sha256sum. The checksums give integrity against the manifest you trust; a checksum file next to the archives is not independent publisher authentication.
  3. Extract only bin/mantle-release from the checked GNU archive and run verify. No compiler is needed.
  4. install --prefix DIR stages the verified files under DIR/.mantle/generations/ and activates the whole generation with one symlink rename. Concurrent installers serialize on a lock and give up after waiting five seconds. It refuses unmanaged files in the way, links inside the prefix, targets other than x86_64-unknown-linux-gnu, and existing generations that were modified, including extra files or directories. Earlier generations are kept; configuration and credentials are outside the prefix. An interruption before activation leaves the previous installation in place.
  5. The worker bundle is never activated by install. A new worker takes it through worker up --binaries; an existing worker needs an offline upgrade.

Development candidates: every CI run that passes the gate (pushes to main, pull requests, tags) builds and verifies a bundle from its exact commit and keeps it as a workflow artifact for 30 days. Its manifest names that commit.

04 / Build from source

Without a release bundle.

Needs Rust 1.97 (rust-toolchain.toml), go-task, the x86_64-unknown-linux-musl Rust target and a musl C toolchain (musl-tools on Ubuntu).

git clone https://github.com/beyond10x/mantle.git
cd mantle
git checkout 0.2.0
cargo install --locked --path crates/mantle
rustup target add x86_64-unknown-linux-musl
task build-worker

task build-worker writes the static helpers to ~/.cache/b10x-target/mantle/x86_64-unknown-linux-musl/release, which is the default of mantle worker up --binaries. The CLI pins Substrate’s SDK to revision 65304edf6ebdf4a95f9c2c6138b0c20ea47d157e (0.7.10).

05 / Specification

Behaviour you can inspect and check.

Six ESS domains describe the implemented behaviour: sessions, manifests, egress, the launcher, orchestration and operator workflows. Native scenarios run production code (SQLite transactions, parsers, TCP tunnels, PTYs, provider decisions, offline installation) with controlled external IO. They do not provision AWS or KubeVirt, run a Substrate daemon or attest to a live deployment.

06 / For maintainers

Building and publishing a release.

Not needed to use Mantle.

Build

Install cargo-about 0.9.1, the Rust musl target and a musl C toolchain. Build only from a clean, exact checkout, with a new work directory and output path:

cargo run --locked -p mantle-release -- notices --check
cargo run --locked -p mantle-release -- build --source "$PWD" \
  --revision "$(git rev-parse HEAD)" --work "$HOME/.cache/mantle-release-build-UNIQUE" \
  --output "$HOME/.cache/mantle-release-bundle-UNIQUE"

Regenerate the committed notice with mantle-release notices when the locked dependency graph changes. The build exports the commit into an isolated tree checked against the raw committed tree and blob bytes, with a fresh target directory. Export attributes that rewrite or omit committed files are refused; Git replacement objects are ignored. Both artifacts are verified by running their version commands; source and compiler logs stay in the work directory. Existing binaries cannot be supplied or relabelled as the chosen commit.

Publish

Publication is an explicit operator command, after the required repository checks pass and the bot has created the tag:

mantle-release publish --manifest /path/to/bundle/manifest.json --source "$PWD" \
  --tag VERSION --policy /path/to/private/gates-policy.json

It uses the installed b10x-gates gh bot wrapper, checks the local and fully dereferenced remote tag against the source, refuses an existing release, uploads only the verified assets and checks GitHub’s resulting asset digests. A failure may leave a partial release for inspection; the command never overwrites it. CI holds no publishing credentials, and no personal gh account writes.
