01 / Architecture

Keep the work where it runs.

Mantle places and connects the session. Substrate owns execution, workspaces, secrets, and the confinement boundary.

The execution foundation

What is Substrate?

Read the Substrate docs ↗

Substrate turns a Linux host into a service for confined workspaces and processes. It enforces the limits the host supports and reports what actually happened. Mantle uses that service to place your development session, start the agent, and connect your terminal.

Trust the host operator. Host administration, including mantle worker ssh, sits outside session confinement. The sandbox is not a boundary against the worker administrator.

Understand credential access. Claude receives its token in its environment; child tools may inherit it. Codex uses device login and a private workspace auth file that its tools can also access. Ordinary mantle exec requests inject no agent credential, but share the workspace. The Claude worker token file remains after session stop.

01

Detach without ending the agent

The launcher holds the agent on a pseudo-terminal. A terminal attachment can end while that agent keeps running, up to its execution lease.

02

Choose a worker provider

AWS uses an SSM tunnel with no inbound security-group ports. KubeVirt uses a VM and provider tunnel. The current slice selects one worker.

03

Read what actually happened

Recorded intent and live Substrate observations are distinct. Unknown execution outcomes and unenforced resource requests stay visible.

02 / Get started

From a manifest to a session.

This is an early preview for Linux x86-64 laptops and AWS or KubeVirt workers. These commands describe 0.2.0; historical 0.1.4 behavior is labeled separately. Choose a verified release bundle or the source build below, then configure your provider. See profiles, doctor and offline upgrades.

  1. Build from source, or install a verified release bundle

    Install Rust 1.97, the Task runner, a musl C toolchain, and SSH. Worker binaries currently target x86-64 Linux. The repository pins Substrate’s SDK. Check out the 0.2.0 tag to build this release. Release bundles require no local Rust build; fresh provisioning accepts their static helpers through worker up --binaries.

    git clone https://github.com/beyond10x/mantle.git
cd mantle
git checkout 0.2.0
cargo install --locked --path crates/mantle
rustup target add x86_64-unknown-linux-musl
task build-worker

    For contributor checks, also install ESS 0.50.x and AEP 0.68.0. Tool versions are pinned in CI.

  2. Configure the worker and credential source

    Copy examples/config.toml to ~/.config/mantle/config.toml. Replace all placeholders and choose provider = "aws" or "kubevirt".

    For AWS, install AWS CLI v2 and Session Manager Plugin, authenticate the chosen profile, and select your VPC and subnet. The account needs the EC2, IAM and CloudWatch permissions used by worker provisioning. For the local KubeVirt test bed, install Docker, k3d and kubectl, then run task k3d-up; nested virtualization must be available.

    For Claude Code, obtain your OAuth token with claude setup-token and store it in a keyring. Configure claude.token_command to retrieve it. An owner-protected token_file is supported when no keyring is available. Keep credentials and account identifiers outside the repository. Codex instead uses ChatGPT device login in its terminal; it needs neither a Claude token nor an API key.

  3. Describe your session

    Save this as mantle.yaml. This example selects Claude Code with the rust-dev runtime. For Codex, use the manifest and login steps below. Sources must be HTTPS repositories reachable through the gateway.

  4. Bring up the worker and start

    mantle worker up
mantle start mantle.yaml

    First boot provisions the worker and installs the pinned toolchain and Mantle binaries. Use --detached on start to start without attaching. Press Ctrl + ], then d, to detach; mantle attach my-project returns to the terminal.

    Historical release 0.1.4 cleanup.

    In release 0.1.4, mantle stop my-project stops the agent and destroys its workspace. In 0.2.0, stop retains it; see retained workspaces. Save wanted changes remotely first. mantle worker down stops the worker while retaining its data volume. Retained cloud storage can still incur charges.

Codex sessions

Choose Codex in your manifest.

The worker installs pinned Codex 0.153.4. Select agent.kind: codex and agent.auth: chatgpt-device, or use the complete example. Omitting the agent kind keeps Claude Code as the default.

mantle worker up
mantle start examples/codex.yaml
# Complete ChatGPT device login in the terminal when prompted.
# Ctrl-] then d detaches; return with:
mantle attach codex-example
mantle status codex-example

Mantle 0.2.0 needs matching worker binaries, Substrate 0.7.10 and the gateway destinations. Existing workers need a coordinated upgrade. Worker readiness verifies the installation and confinement, not your authentication. Use --detached to start first and log in after attaching.

Know what is retained.

Codex uses the same Substrate terminal transport and capture behavior as Claude. This is not an end-to-end non-recording mode. Auth and conversation files stay in the private workspace home; launcher replay is volatile and SQLite/text diagnostics use verified tmpfs. Historical release 0.1.4 mantle stop codex-example destroys that workspace and its login state. In 0.2.0, stop retains both; explicit destroy NAME --yes deletes them. Save wanted work remotely first.

Device login, authenticated model/tool turns and token refresh still require end-to-end verification. Read the qualification evidence for observed behavior and remaining limits.

For automation, use versioned metadata and creation receipts. JSON list stays local; status separates recorded state from available or refused remote observations. Human status may print launcher diagnostics.

In 0.2.0, mantle exec preserves remote exit codes 0–255 and maps INT/TERM/KILL to 130/143/137. Refused, missing, contradictory or indeterminate results return failure. stdout and stderr retain their bytes after successful SDK-envelope decoding; the status diagnostic follows stderr. Malformed responses fail without raw-output recovery. This fixes the false-success behavior of historical 0.1.4.

04 / Current boundaries

Explicit about what is enforced.

Network

The default CONNECT gateway admits ten exact HTTPS destinations for Anthropic, ChatGPT, OpenAI authentication, GitHub and crates.io. Codex uses auth.openai.com:443 and chatgpt.com:443. It rejects IP-literal targets and non-public resolved addresses. Naming a subset of manifest capabilities does not narrow this fixed allowlist.

Resources

Memory and process limits depend on the worker’s reported Substrate facts. CPU sets build parallelism through CARGO_BUILD_JOBS; it does not enforce CPU bandwidth. Storage quotas are conditional on worker support.

Credentials

The Claude token enters the sandbox through Substrate’s claude secret slot and the launcher’s inherited descriptor. Codex uses ChatGPT device login and stores its auth file under /workspace/.mantle/home/.codex. Normal session execs receive no injected agent credential but can access the shared workspace. The Claude worker token file remains after session stop.

Durability

Detach preserves the running agent, subject to its lease. Retention is positive and at most 24 hours. Worker failure recovery, snapshots, shared caches, peer networking and fleet scheduling are outside the implemented slice.

Version 0.2.0

Verified Linux bundles.

Release 0.2.0 provides verified bundles for the Linux x86-64 GNU laptop CLI and static musl workers.

The GNU bundle installs mantle, mantle-release and mantle-acceptance together. Each bundle has a strict manifest bound to its exact source commit, Substrate pin, toolchain, runtime and payload checksums. Both archives carry complete dependency and Rust runtime notices; workers also carry the matching musl notice. GNU compatibility is limited to the runtime recorded in the manifest. Other platforms and older libc versions are not qualified.

Download the assets from the 0.2.0 release and check the tagged source identity in its manifest. Development candidates remain available from their trusted CI run. Keep both archives beside the manifest and verify their hashes before extracting the bundled mantle-release verifier. No installer source build is required. Checksums establish integrity against the supplied manifest, not independent publisher authentication. Follow the bootstrap and installation instructions.

./bootstrap/bin/mantle-release verify --manifest "$PWD/manifest.json"
./bootstrap/bin/mantle-release install --manifest "$PWD/manifest.json" \
  --prefix "$HOME/.local/mantle"

The GNU installer refuses unmanaged collisions and activates a complete verified generation under a bounded exclusive lock. Previous generations remain available; configuration and credentials are outside installation. Worker bundles require the explicit offline upgrade path or fresh delivery and are never activated by the GNU installer. CI retains candidates without publishing credentials; operator publication uses the bot wrapper, checks exact remote tags, and refuses existing releases or assets.

Version 0.2.0

Upgrade helpers during explicit maintenance.

Release 0.1.4 does not include these commands. Use a matching 0.2.0 CLI and verified bundle. Substrate must already match the exact supported pin; this command does not migrate or replace Substrate.

mantle worker upgrade --check --manifest "$PWD/manifest.json"
mantle worker upgrade --apply --manifest "$PWD/manifest.json"

Check observes older workers through bounded read-only SSH probes without uploading a helper. Apply requires an exclusive administrator maintenance window: both services already inactive, effectively masked and reloaded, no pending jobs or PIDs, and empty supported cgroup trees. Preserve the exact original units under the private maintenance directory before masking; ordinary masks cannot replace the existing regular files in /etc/systemd/system. Follow the complete preparation, recovery and restoration procedure.

Apply verifies and stages a complete helper directory, preserves Claude and the Codex generation link, and atomically exchanges directories under the shared installation lock. Workspaces, configuration, secrets and agent generations remain in place. A synced journal and prior directory support recovery; failed restoration is reported as recovery-required. Success is applied-restart-required: the command never stops, masks, starts or restarts services. Exclude other administrators and older clients for the entire maintenance window. Managed helpers subsequently refuse replacement through worker up. Fresh workers can use verified static prebuilt helpers through the documented worker up --binaries flow without building Rust sources.

Version 0.2.0

Keep workspaces after stopping.

Stop changes meaning: 0.2.0 stop terminates and retires the agent while preserving edited files and its private login home. Release 0.1.4 still deletes them.

mantle stop my-project
mantle restart my-project
mantle destroy my-project --yes

Restart uses the same workspace and immutable persisted agent, cwd and resource policy. It creates a fresh process without cloning repositories or overwriting login files; it does not promise same-conversation resume. Attach never starts an agent. Missing workspaces are refused, never recreated. Retained names remain reserved.

Attach, exec, stop, restart and destroy accept --expected-session-id ID to refuse a reused name before mutation. Durable attempts serialize conflicting commands. Retry the same command after interruption: restart observes its original admission operation, and unknown results stay incomplete instead of launching duplicates. Confirmed running or terminal admissions can be cleaned up even when readiness failed. Unproven interrupted initial materialization stays incomplete.

Historical STOPPED means destroyed. Migration preserves historical STOPPING as destructive intent; retrying it can still delete the workspace. Legacy records without launch context, changed worker bindings and unsupported policy versions cannot invent a restart from current configuration. Worker or volume loss recovery is not provided; retained storage may still incur charges.

Version 0.2.0

Keep named environments separate.

These commands are available in 0.2.0. Use the matching CLI.

mantle profile add personal --config "$HOME/.config/mantle/personal.toml" --state-dir "$HOME/.local/state/mantle-personal"
mantle profile list
mantle profile show personal
mantle --profile personal list
MANTLE_PROFILE=personal mantle worker status

Profiles store absolute path references in private files under ~/.config/mantle/profiles/. Registration, listing and showing do not read provider configuration, contact workers or copy credentials. Names start with a lowercase letter or digit and use lowercase letters, digits, underscores or hyphens, up to 63 characters. Existing names cannot be overwritten.

--profile overrides MANTLE_PROFILE. Unset MANTLE_CONFIG and MANTLE_STATE_DIR before selecting a named profile; combining them is refused. Without a profile, the existing variables and defaults still work. Use a different private state directory for each profile to separate SQLite records, SSH keys and known hosts. Attachments use distinct short private temporary sockets, including with long or Unicode state paths. Profile entries and selected paths refuse symlinks, nonregular files and unsafe directory permissions. State paths support spaces, #, colons and Unicode; quotes, backslashes, percent tokens and ${...} expressions are refused because OpenSSH interprets them.

Version 0.2.0

Diagnose an existing worker.

Use the 0.2.0 CLI or verified release bundle for doctor.

mantle --profile personal doctor
mantle --profile personal doctor --json --timeout-secs 5

Checks run in order: configuration, recorded worker and placement, provider, strict SSH, Substrate service/socket, installed Mantle versions, live Substrate compatibility and common confinement facts. Results are healthy, failed or skipped. An early failure suppresses dependent probes and returns a nonzero exit status; JSON stays structured even if selection fails. Reports provide fixed advice without raw provider, SSH or configuration contents. Readiness does not establish agent authentication.

Doctor requires existing keys and pinned known hosts. It does not accept new hosts, invoke agent credential commands, initialize or migrate a database, change application records or restart services. SQLite reads current committed WAL data using read-only/query-only access; normal locking/shared-memory coordination is allowed. Existing provider authentication plugins may run. Each external probe defaults to 10 seconds, configurable from 1 to 120; owned process groups and tunnel descendants are retired on timeout. Configuration reads are capped at 1 MiB, database/sidecar files at 64 MiB, and SQLite busy/query handling at 250 milliseconds.

Version 0.2.0

Repeat qualification through the installed CLI.

mantle-acceptance uses the same case inventory for disposable Claude Code and Codex sessions. It is included in the GNU 0.2.0 bundle. Choose an already configured qualification worker and named profile; the runner does not provision workers or adopt user sessions.

Login, model/tool action and visual checks run in your own terminal through the printed attach command. Explicit operator attestations stay separate from machine observations. Missing manual evidence leaves qualification incomplete; a running agent is not proof of authentication. The runner records bounded metadata, without terminal transcripts or auth-cache inspection.

Private checkpoints bind the run to its executable, resolved profile and owned session/workspace/exec identities. Cleanup requires the successful creation receipt; a later matching name is insufficient. An interrupted receipt stays unresolved. Retained-workspace checks observe the same workspace and synthetic marker with a new agent process, without claiming conversation resume.

Known source requires a supplied verified manifest, its sibling archives and a matching installed CLI digest. Omit --release-manifest to record unknown source identity; a supplied invalid or mismatching bundle is refused. Exit 2 means incomplete/operator action required, exit 1 means failure, and exit 0 means all required cases are complete. Report and cleanup preserve that aggregate status, so successful cleanup after an incomplete run still returns 2. Controlled CLI/PTY tests verify the runner, not full live authentication. Follow the acceptance procedure; historical qualification limits still apply.

06 / Troubleshooting

Start with the observation.

The worker is not ready

Run mantle worker status. For a new worker, mantle worker up finishes bootstrap. For an existing worker with sessions, follow the coordinated upgrade guidance before changing services. The CLI checks that bootstrap completed and Substrate is active before connecting. Verify your provider configuration and token source.

A session exists, but attach fails

mantle list shows recorded intent. Use mantle status NAME for live observations. If the agent has exited, attachment cannot restart it. With 0.2.0, stop retains the workspace and restart creates a fresh process. Attach never restarts it. Historical release 0.1.4 stop destroys the workspace; preserve needed work first.

A repository cannot be fetched

Check that the URL is HTTPS, the ref exists, and the host is admitted by the fixed egress allowlist. The initial slice does not provide a Git credential broker. The example uses a public GitHub repository.

A resource request says “not enforced”

The CLI reports the worker’s actual capabilities. It does not turn a request into proof of enforcement. Check the relevant Substrate fact; CPU bandwidth control is not implemented by this slice.

Historical release 0.1.4

Codex integration, with recorded acceptance.

This patch release integrates the final release and acceptance records and refreshes the documentation. Runtime behavior is unchanged from 0.1.3. The operator confirmed that attachment worked with the corrected CLI and worker profile; full authenticated lifecycle qualification remains incomplete.

Attachment replay starts after the client is ready. With Substrate 0.7.10, a full live-output queue waits up to one second per frame for its consumer. Queue and output bounds remain enforced; a stalled consumer can still end an attachment.

An isolated, confined synthetic test delivered the full 256 KiB replay twice through real PTYs, preserved keyboard input and terminal settings, and detached and reconnected to the same agent. An isolated KubeVirt worker running the signed Substrate 0.7.10 runtime also passed two real Codex 0.153.4 attachments through 100×50 PTYs. Each ran for 12 seconds and detached with exit 0; reconnection preserved the same agent. The original worker and sessions were preserved. These transport checks do not establish visually inspected screen correctness, device login, authenticated model/tool turns, token refresh or full live lifecycle parity.

Historical 0.1.4 worker compatibility.

Use the matching 0.1.4 laptop CLI and worker binaries with Substrate 0.7.10. Check mantle list and mantle status NAME, preserve wanted project changes and workspace data, and schedule maintenance before replacing a running daemon.
