01

Detach without ending the agent

The launcher holds the agent on a pseudo-terminal. A terminal attachment can end while that agent keeps running, up to its execution lease.

02

Choose a worker provider

AWS uses an SSM tunnel with no inbound security-group ports. KubeVirt uses a VM and provider tunnel. The current slice selects one worker.

03

Read what actually happened

Recorded intent and live Substrate observations are distinct. Unknown execution outcomes and unenforced resource requests stay visible.

02 / Get started

From a manifest to a session.

This is an early source-built preview. Use a Linux laptop and a test worker environment; there is no packaged Mantle release yet.

  1. Build the tools

    Install Rust 1.97, the Task runner, a musl C toolchain, and SSH. Worker binaries currently target x86-64 Linux. The repository pins Substrate’s SDK.

    git clone https://github.com/beyond10x/mantle.git
cd mantle
cargo install --locked --path crates/mantle
rustup target add x86_64-unknown-linux-musl
task build-worker

    For contributor checks, also install ESS 0.50.x and AEP 0.68.0. Tool versions are pinned in CI.

  2. Configure the worker and credential source

    Copy examples/config.toml to ~/.config/mantle/config.toml. Replace all placeholders and choose provider = "aws" or "kubevirt".

    For AWS, install AWS CLI v2 and Session Manager Plugin, authenticate the chosen profile, and select your VPC and subnet. The account needs the EC2, IAM and CloudWatch permissions used by worker provisioning. For the local KubeVirt test bed, install Docker, k3d and kubectl, then run task k3d-up; nested virtualization must be available.

    Obtain your Claude Code OAuth token with claude setup-token and store it in a keyring. Configure claude.token_command to retrieve it. An owner-protected token_file is supported when no keyring is available. Keep credentials and account identifiers outside the repository.

  3. Describe your session

    Save this as mantle.yaml. The first slice serves Claude Code with the rust-dev runtime. Sources must be HTTPS repositories reachable through the gateway.

    apiVersion: mantle.beyond10x.dev/v1alpha1
kind: Session
metadata:
  name: my-project
runtime:
  profile: rust-dev
workspace:
  repositories:
    - name: mantle
      repository: https://github.com/beyond10x/mantle.git
      ref: main
      mount: mantle
agent:
  kind: claude-code
  cwd: /workspace/mantle
resources:
  cpu: 4
  memory: 16GiB
  pids: 4096
lifecycle:
  detachKeepsRunning: true
  retainFor: 8h

  4. Bring up the worker and start

    mantle worker up
mantle start mantle.yaml

    First boot provisions the worker and installs the pinned toolchain and Mantle binaries. Use --detached on start to start without attaching. Press Ctrl + ], then d, to detach; mantle attach my-project returns to the terminal.

    Cleanup has two distinct effects.

    mantle stop my-project stops the agent and destroys its workspace. Save wanted changes remotely first. mantle worker down stops the worker while retaining its data volume. Retained cloud storage can still incur charges.

03 / CLI reference

The session controls.

Mantle commands and their behavior
CommandWhat it does
mantle worker upCreate or start the selected worker, install binaries, and check Substrate facts.
mantle worker statusShow provider state and the worker’s observed capabilities.
mantle worker sshOpen a host shell through the provider tunnel, outside the sandbox.
mantle worker downStop the worker; retain its data volume.
mantle start [manifest] [--detached]Resolve a manifest, materialize repositories, start Claude Code, and optionally attach.
mantle attach NAMEAttach to the agent terminal. One attachment at a time.
mantle listList locally recorded sessions that are not stopped.
mantle status NAMEShow recorded intent, resolved sources, requested limits and current observations.
mantle exec NAME -- PROGRAM ARGSRun a command with the session’s confinement and toolchain, without the agent credential.
mantle stop NAMERetire the agent and destroy the workspace. Interrupted cleanup resumes from Stopping.

04 / Current boundaries

Explicit about what is enforced.

Network

The default CONNECT gateway admits eight exact HTTPS destinations for Anthropic, GitHub and crates.io. It rejects IP-literal targets and non-public resolved addresses. Naming a subset of manifest capabilities does not narrow this fixed allowlist.

Resources

Memory and process limits depend on the worker’s reported Substrate facts. CPU sets build parallelism through CARGO_BUILD_JOBS; it does not enforce CPU bandwidth. Storage quotas are conditional on worker support.

Credentials

The Claude token enters the sandbox through Substrate’s claude secret slot and the launcher’s inherited descriptor. Normal session execs receive no agent credential. The worker’s token file remains after session stop.

Durability

Detach preserves the running agent, subject to its lease. Retention is positive and at most 24 hours. Worker failure recovery, snapshots, shared caches, peer networking and fleet scheduling are outside the implemented slice.

06 / Troubleshooting

Start with the observation.

The worker is not ready

Run mantle worker status, then mantle worker up to finish bootstrap. The CLI checks that bootstrap completed and Substrate is active before connecting. Verify your provider configuration and token source.

A session exists, but attach fails

mantle list shows recorded intent. Use mantle status NAME for live observations. If the agent has exited, attachment cannot restart it. Save any needed work before mantle stop NAME destroys the workspace.

A repository cannot be fetched

Check that the URL is HTTPS, the ref exists, and the host is admitted by the fixed egress allowlist. The initial slice does not provide a Git credential broker. The example uses a public GitHub repository.

A resource request says “not enforced”

The CLI reports the worker’s actual capabilities. It does not turn a request into proof of enforcement. Check the relevant Substrate fact; CPU bandwidth control is not implemented by this slice.
