Upstream describes pre-1.0 releases as beta. This probe used one native X25519 recipient and binary output, with no armor or plugins.

For this exact implementation, let n be plaintext bytes, C=max(1,ceil(n/65536)), and G be the randomized GREASE stanza bytes. The complete binary age body is exactly:

`A(n,G) = 21 + 98 + G + 48 + 16 + n + 16*C = n + 183 + G + 16*C`.

Those terms are the version line, X25519 stanza, GREASE stanza, header MAC line, payload nonce, plaintext, and chunk tags. The [official format](https://c2sp.org/age@v1.1.0) specifies the chunk boundaries and required final chunk. The pinned [header implementation](https://github.com/str4d/rage/blob/7a854c9c8c02dab2ebea19e02e6693a5730a8b2a/age/src/format.rs) adds GREASE for this recipient.

The [pinned age-core source](https://github.com/str4d/rage/blob/f6383f367e9aa514a3b5fbce7feede08a425d647/age-core/src/format.rs) samples a 1..=8-character tag prefix plus `-grease`, 0..=4 arguments of 1..=8 characters, and 0..=99 body bytes. Therefore G is 13..=190 bytes: maximum argument line 3+15+4*(1+8)+1=55; maximum encoded body 132 characters plus 3 newlines=135. The source comments are loose; the exclusive Rust range endpoints determine this bound. The probe serialized both exact extreme stanzas through the crate's real encoder, obtaining 13 and 190. This is a source-derived maximum, not a sampled maximum. It is not a bound for arbitrary age files, multiple recipients, armor, or a future dependency.

For 0<=n<=65536, A<=n+389; the 4-byte frame prefix gives W<=n+393. Results from the actual generated ESS model, with sequence u64::MAX, version 1 and 32 lowercase hex stream ID:

Standard canonical base64 needs 4*ceil(4096/3)=5464 characters. All its characters serialize without JSON escaping in this serializer; content does not affect this maximum. The JSON cap 24576 and encrypted-body cap 32768 have ample room. A complete End reserve of 4096 permits End plaintext up to 3703 bytes; the largest current End is 151. Preserve the explicit End size assertion so future schema growth cannot invalidate the reserve.

Budget rule: keep `used = sum(4 + actual_finalized_age_body_len)` including End. Before reading more terminal bytes require `cap - used >= (32768 + 4) + 4096 = 36868`, using checked arithmetic and serialized access to the counter/queue. Charge all accepted/queued bytes immediately, never just completed OS writes. The final complete End must fit the reserved 4096 and keep `used <= 1048576`. The probe's conservative accounting allows 41 records at the proven generic maximum 24969, leaving 24847 bytes; End still fits. This is a ciphertext cap, not 1 MiB of terminal plaintext. Scheduling, a blocked reader, FIFO ownership, and End emission are implementation obligations beyond this arithmetic proof.

Finalize each independent age file with `StreamWriter::finish()` before framing/emission. Read the outer advertised body exactly after checking 1..=32768, decrypt that bounded slice to a separate buffer, and propagate every read error before releasing any terminal output. The probe uses `reader.take(24577).read_to_end(...)` and rejects decoded length above 24576: the extra byte avoids accepting a capped read without reaching authenticated EOF at exactly the allowed length. Never ignore `read_to_end` errors. The [stream implementation](https://github.com/str4d/rage/blob/7a854c9c8c02dab2ebea19e02e6693a5730a8b2a/age/src/primitives/stream.rs) checks the final marker. Validate the generated record's semantics only after decryption succeeds. Missing End, trailing records, stream identity and sequence are application protocol checks, not age checks.

Observed refusals in `green-final.log`: wrong identity and tampered wrapped file key both return `NoMatchingKeys`; header MAC tampering returns `InvalidMac`; payload tag tampering, appended bytes, concatenated files, and some suffix truncations return `io::ErrorKind::InvalidData`. Header/nonce truncation returns an I/O UnexpectedEof through DecryptError; a missing final chunk returns stream UnexpectedEof. Thus `Key` can mean no matching decryptable stanza, not proof of a wrong private key. Authentication failure cannot reliably distinguish ciphertext corruption from every truncation: classify outer short reads and explicit UnexpectedEof as Truncated, InvalidMac/InvalidData as Authentication (or a documented combined integrity failure), and retain a fail-closed fallback for non-exhaustive errors. The [X25519 source](https://github.com/str4d/rage/blob/7a854c9c8c02dab2ebea19e02e6693a5730a8b2a/age/src/native/x25519.rs) intentionally cannot tell which private key matches a stanza.

Age provides recipient confidentiality and ciphertext integrity; it does not establish sender identity. Anyone with the public recipient can encrypt a fresh file.
