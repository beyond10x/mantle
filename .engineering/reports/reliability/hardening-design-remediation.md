## Fixture reuse and costs

Feasible without recursive Cargo. Existing release Fixture and GNU/musl ELF preparation are in crates/mantle-release/tests/release.rs:12–114; orchestration.rs currently duplicates packaging preparation. Extract shared test support returning measured observations; keep the independent system SHA256 oracle in release.rs:31. Existing small transport programs compile with rustc, not Cargo. Share their compilation once per run where practical.

There is one real integration dependency: current native CLI conformance is a unit test (adapters/conformance.rs:337), while real CLI integration tests obtain Cargo-built executables through CARGO_BIN_EXE_mantle / CARGO_BIN_EXE_mantle-release. A unit test does not automatically receive those paths. Wire an explicit already-built binary path from the outer gate, or host the subprocess-backed ESS boundary in an integration-test target with the existing report aggregation. Fail closed if the exact candidate executable is unavailable. Do not discover an arbitrary PATH/target binary, call cargo recursively, or translate a package test's successful exit into invented observations. This plumbing is the largest common dependency for HD-02–05,07–08; avoid separate harnesses for each finding.

Core contract changes precede adapter changes, followed by generated suite/baseline reconciliation. No new public Mantle runtime capability is needed. Real release-build provenance cannot honestly be replaced by a tiny fixture; retain CI source-build evidence and narrow ESS assertions to the production source/export/verifier seams actually executed.
